# 우리장부 PRD v1.2 — Firebase 배포본

- 문서 기준일: 2026-10-09
- 제품 상태: Firebase Hosting 배포 완료
- 대상 플랫폼: PC·모바일 반응형 웹
- 제품명: 우리장부

## 1. 제품 개요

우리장부는 개인 또는 가족이 카드·은행 거래 파일을 가져와 소비를 정리하고, 예산·자산·투자·대출을 월 단위로 확인하는 가계부 웹 서비스다.

핵심 가치는 다음 세 가지다.

1. 회사마다 다른 거래 파일을 가능한 한 자동으로 읽고, 자동 인식이 실패한 경우에만 최소한의 열 연결을 요청한다.
2. 월별 지출과 결제수단 실적, 자산과 대출을 한 화면 흐름에서 관리한다.
3. 로그인 없이 개인 장부를 사용하고, 필요할 때 Google 계정으로 로그인해 초대한 가족과 하나의 장부를 함께 관리한다.
4. 실제 금융기관 로그인 정보나 원본 파일을 서버에 보관하지 않고도 사용자가 자신의 재무 상태를 파악할 수 있게 한다.

## 2. 제품 목표

### 2.1 사용자 목표

- 거래 파일을 업로드해 수입·지출을 빠르게 등록한다.
- 거래처·분류·작성자·결제수단·월 조건으로 거래를 찾고 필터 합계를 확인한다.
- 카드 혜택을 위해 필요한 월 목표 사용액과 현재 달성률을 확인한다.
- 월별 예산과 저축 목표를 설정하고 실제 지출과 비교한다.
- 예금, 투자, 대출을 합산해 순자산과 예상 이자 흐름을 파악한다.
- 이전 달 자산 기록을 이어받아 변경된 부분만 수정한다.
- 가족을 링크 또는 코드로 초대하고 같은 장부의 변경 내용을 공유한다.

### 2.2 제품 목표

- 처음 보는 거래 파일도 사용자 개입을 최소화해 수용한다.
- 날짜·금액·카테고리 계산 오류를 방지한다.
- 빈 상태에서도 사용자가 다음 행동을 이해할 수 있게 한다.
- PC와 모바일에서 동일한 핵심 기능을 제공한다.
- 배포 전에는 실제 사용자 데이터 대신 가상 발표 자료로 기능을 시연할 수 있게 한다.

## 3. 주요 사용자

### 3.1 개인 사용자

- 본인의 거래, 예산, 자산, 투자, 대출을 관리한다.
- 닉네임을 설정하고 거래 작성자로 사용한다.

### 3.2 가족 사용자

- 두 사람의 거래를 작성자별로 구분한다.
- 자산과 부채를 작성자별로 기록하고 가정 전체 금액을 합산한다.
- Google 계정으로 로그인한 뒤 소유자가 발급한 초대 링크 또는 코드로 공동 장부의 접속 권한을 요청한다.
- 가정 소유자는 새 초대 코드를 발급하고 접속 요청을 승인·거절할 수 있으며, 승인된 구성원만 공동 장부를 조회·수정할 수 있다.

## 4. 정보 구조

1. 홈(대시보드)
2. 거래 내역
3. 예산·고정비
4. 자산·투자
5. 설정

PC에서는 왼쪽 사이드바, 모바일에서는 하단 내비게이션을 사용한다.

## 5. 기능 요구사항

## 5.1 홈 대시보드

### 순자산 요약

- 현금성 자산, 투자자산, 대출 원금을 합산한다.
- 순자산은 `현금성 자산 + 투자 평가액 - 대출 원금`으로 계산한다.
- 자산 기록이 없으면 등록 안내를 표시한다.

### 월별 거래 요약

- 선택된 기준 월의 수입, 지출, 예상 저축을 표시한다.
- 예상 저축은 `수입 - 지출`로 계산한다.
- 카드 미결제액 카드 대신 지난달 총지출을 표시한다.
- 지난달 기록이 있으면 이번 달과의 차이를 함께 안내한다.

### 예산 현황

- 설정한 카테고리별 예산과 실제 사용액을 표시한다.
- 예산이 없으면 예산 설정 화면으로 이동할 수 있는 빈 상태를 표시한다.

### 항목별 지출

- 이번 달 지출을 카테고리별 원형 도표로 표시한다.
- 각 항목의 금액, 비중, 지난달 대비 증감률을 표시한다.
- 상위 항목과 그 외 항목을 구분해 가독성을 유지한다.

### 최근 거래

- 최근 거래 5건을 표시한다.
- 전체 거래 화면으로 이동할 수 있다.

## 5.2 거래 내역

### 직접 입력

- 거래처, 금액, 카테고리를 입력해 지출을 추가한다.
- 직접 입력한 거래에는 현재 날짜와 사용자 닉네임을 사용한다.
- 거래는 수정·삭제할 수 있다.

### 거래 파일 가져오기

- 허용 형식: `.xls`, `.xlsx`, `.csv`
- 지원 양식은 자동 인식한다.
- 현재 우선 지원 대상은 우리장부 거래 양식, 일반 카드 이용내역, NH농협카드 이용내역, 하나카드, IBK기업은행이다.
- 우리장부 거래 양식을 다시 가져오면 전체 거래를 해당 파일 내용으로 갱신한다.
- 카드·은행 원본은 기존 거래에 추가한다.
- 취소 거래, 카드대금 납부 등 중복 소비가 될 수 있는 행은 명세에 따라 제외한다.

### 미지원 양식 처리

- 지원 형식으로 인식되지 않을 때만 수동 열 연결 화면을 표시한다.
- 필수 연결 항목은 날짜, 거래처, 금액이다.
- 선택 항목은 취소·상태, 카드·계좌다.
- 확인한 헤더 조합과 열 연결을 브라우저에 저장한다.
- 같은 양식은 다음 업로드부터 저장된 연결을 자동 적용한다.

### 날짜 처리

- 엑셀 날짜는 시간대 변환 전의 일련번호를 기준으로 읽는다.
- 자정 기준 날짜를 `Date` 객체로 먼저 변환하지 않아 하루 전날로 밀리는 문제를 방지한다.
- `YYYY-MM-DD` 형식으로 정규화해 화면과 내보내기에 사용한다.

### 거래 내보내기

- 현재 거래 전체를 우리장부 엑셀 양식으로 내려받는다.
- 날짜 오름차순으로 정렬한다.
- 작성자, 거래처, 분류, 결제수단, 구분, 금액을 포함한다.
- 분류 마스터 시트를 함께 제공한다.

### 검색과 필터

- 거래처, 분류, 계좌·카드, 작성자 통합 검색을 지원한다.
- 월, 작성자, 계좌·카드별 필터를 지원한다.
- 필터 초기화를 제공한다.
- 거래 목록 제목에 필터 결과 건수를 표시한다.

### 거래표 합계

- 거래표 맨 아래에 현재 필터 결과의 총액을 표시한다.
- 수입 합계와 지출 합계를 각각 표시한다.
- 최종 총액은 `수입 - 지출`로 계산한다.
- 검색어 또는 어떤 필터가 변경되더라도 합계를 즉시 다시 계산한다.

### 혜택 카드 사용 현황

- 모든 결제수단을 자동 나열하지 않는다.
- 사용자가 직접 지정한 혜택 카드만 표시한다.
- 혜택 카드 설정 항목은 결제수단, 월 목표 사용액, 카드 혜택 설명이다.
- 카드별 현재 사용액, 목표 사용액, 달성률, 목표까지 남은 금액을 표시한다.
- 목표를 달성하면 달성 메시지를 표시한다.
- 카드 모양의 요약 영역에 결제수단명과 혜택 설명을 표시한다.
- 혜택 카드는 추가·수정·삭제할 수 있다.
- 혜택 카드 설정은 브라우저 로컬 저장소에 보관한다.
- 사용액은 현재 거래 필터 기준으로 계산한다.
- 전체 기간이 선택된 경우 월 필터를 선택해야 정확한 월간 실적을 볼 수 있다는 안내를 표시한다.

## 5.3 예산·고정비

### 조회 기준

- 연도와 월을 선택한다.
- 선택한 월의 수입, 지출, 저축 가능 금액을 계산한다.
- 선택 기간의 카테고리별 지출 추이를 차트로 표시한다.

### 예산

- 카테고리별 예산을 추가·수정·삭제한다.
- 전체 사용액과 전체 예산을 비교한다.
- 항목별 사용률과 초과 여부를 표시한다.

### 저축 목표

- 월 저축 목표를 설정·수정한다.
- `월 수입 - 월 지출`을 목표와 비교해 달성률을 표시한다.

### 고정비

- 이름, 금액, 결제일을 입력한다.
- 등록 항목을 수정·삭제할 수 있다.
- 고정비는 홈 대시보드의 핵심 카드에서는 제외한다.
- 향후 실제 거래와의 자동 연결은 후속 범위다.

## 5.4 자산·투자

### 월별 기록과 이월

- 자산 기록은 월별 스냅샷으로 관리한다.
- 선택한 달에 기록이 없으면 가장 가까운 이전 달 기록을 자동으로 이어받는다.
- 이어받은 내용을 수정하거나 파일을 가져오면 해당 월의 별도 기록으로 저장한다.
- 다른 달의 원본 기록은 변경하지 않는다.

### 자산 파일 가져오기

- 자산 전용 `.xlsx` 양식을 제공한다.
- `저축·예금`, `주식·ETF`, `대출` 시트를 읽는다.
- 가져온 파일명과 항목별 건수를 사용자에게 안내한다.

### 저축·예금

- 작성자, 자산명, 금융기관, 현재 잔액, 연이율, 통화를 관리한다.
- 월 예상이자는 `현재 잔액 × 연이율 ÷ 12`로 계산한다.
- 원화 자산의 잔액 합계와 월 예상이자 합계를 표시한다.
- 개별 항목을 추가·수정·삭제할 수 있다.

### 투자 포트폴리오

- 작성자, 종목명, 티커, 시장, 통화, 보유수량, 평균매입가, 총매입금, 현재 평가금을 관리한다.
- 평가손익은 `평가금 - 총매입금`으로 계산한다.
- 수익률은 `평가손익 ÷ 총매입금 × 100`으로 계산한다.
- 외화 종목은 임의 환산하지 않고 통화별 금액을 표시한다.
- 국내 상장 주식·ETF는 6자리 종목코드와 보유수량을 기준으로 최근 종가를 갱신한다.
- 시세는 한국투자증권 Open API를 Cloudflare Worker에서 조회한다. ETF/ETN 현재가를 먼저 조회하고, 일반 국내주식 현재가를 다음으로 조회한다.
- 시세 화면에 한국투자증권 Open API를 출처로 표시하며, 장중에는 현재가가 표시될 수 있음을 안내한다.
- 원본 종가는 변경하지 않고, 사용자의 평가금은 `최근 종가 × 보유수량`으로 구분하여 계산한다.
- 갱신이 성공하면 `최근 종가 × 보유수량`으로 평가금을 다시 계산하고 기준일을 표시한다.
- 한국투자 API에서 조회되지 않는 종목과 종목코드·수량이 빠진 종목은 건너뛰고 사용자에게 확인할 건수를 안내한다.
- 외화 종목은 이번 한국투자 국내 시세 자동 갱신 대상에서 제외하고 사용자가 직접 수정한다.

### 대출·부채

- 작성자, 대출명, 금융기관, 남은 원금, 연 금리를 관리한다.
- 남은 원금 합계를 표시한다.
- 대출별 월 예상이자를 표시한다.
- 전체 월 예상이자 합계를 표시한다.
- 월 예상이자는 `남은 원금 × 연 금리 ÷ 12`로 계산한다.
- 금리가 입력되지 않은 항목은 `금리 입력 필요`로 표시하고 합계에서 0원으로 처리한다.
- 실제 청구 이자는 상환 방식, 변동금리, 일수 계산에 따라 달라질 수 있음을 안내한다.
- 개별 대출을 추가·수정·삭제할 수 있다.

## 5.5 설정

- 내 닉네임과 가족 닉네임을 설정한다.
- 거래 작성자와 자산 작성자에 닉네임을 사용한다.
- 로그인한 Google 계정과 현재 가정 정보를 표시한다.
- 가정 소유자는 7일간 유효한 초대 링크·코드를 발급하거나 갱신한다.
- 초대 링크를 복사해 메신저나 이메일로 직접 공유할 수 있다.
- 초대 링크로 접속한 사용자는 Google 로그인만 하면 별도 코드 입력 없이 접속 권한 요청을 전송한다.
- 초대 코드를 직접 입력한 사용자는 접속 권한을 요청하며, 요청만으로는 장부 정보가 공개되지 않는다.
- 소유자는 요청자의 Google 표시 이름과 이메일을 확인한 뒤 승인 또는 거절한다.
- 구성원 목록과 소유자·구성원 역할을 표시한다.
- 로그아웃할 수 있다.
- 가져오기 지원 범위와 원본 파일 보관 정책을 안내한다.

## 5.6 로그인과 공동 장부

- 개인 장부는 로그인 없이 첫 화면에서 바로 사용하고, 설정 화면에서 Firebase Authentication의 Google 로그인 버튼을 제공한다.
- Firebase Authentication이 Google 로그인 상태를 관리한다.
- Firestore 보안 규칙이 로그인 여부, 가정 구성원 여부, 장부 소유자 권한을 데이터 요청마다 검증한다.
- 최초 로그인 사용자는 개인 가정을 자동으로 생성한다.
- 거래, 예산, 저축 목표, 고정비, 자산 월별 스냅샷, 닉네임을 가정 단위로 저장한다.
- 같은 가정의 구성원은 동일한 공동 장부 스냅샷을 읽고 수정한다.
- 승인 대기 중인 사용자는 자신의 개인 장부만 사용할 수 있으며, 대상 가정의 장부 데이터는 읽거나 수정할 수 없다.
- 원본 금융 파일은 브라우저에서 분석하며 공동 저장소에 보관하지 않는다.
- Firebase 프로젝트 기본 설정을 사용하므로 OAuth 클라이언트 ID를 수동 입력하지 않는다.

## 6. 소비 카테고리

식비, 관리비, 생활용품, 교통비, 주유, 차량관리, 의료비, 운동, 쇼핑, 통신·구독, 보험, 교육·육아, 여행·여가, 경조사·선물, 계모임, 세금·공과금, 금융수수료, 급여, 기타·미분류를 기본으로 사용한다.

거래처 기반 자동 분류 규칙과 상세 가져오기 규칙은 `docs/IMPORT_SPEC.md`를 기준으로 한다.

## 7. 데이터와 저장 정책

### Firebase 배포 저장 구조

| 데이터 | 현재 저장 방식 | 새로고침 후 유지 |
| --- | --- | --- |
| 거래·예산·저축 목표·고정비 | 비로그인 시 `localStorage`, 로그인 시 가정 단위 Firestore | 예 |
| 닉네임 | 비로그인 시 `localStorage`, 로그인 시 가정 단위 Firestore | 예 |
| 자산 월별 스냅샷 | 비로그인 시 `localStorage`, 로그인 시 가정 단위 Firestore | 예 |
| 혜택 카드 설정 | `localStorage` | 예 |
| 미지원 파일 열 연결 | `localStorage` | 예 |
| 업로드 원본 파일 | 메모리에서 분석 후 미보관 | 해당 없음 |

### Firebase 구성

- Firebase Authentication으로 Google 로그인을 제공한다.
- Cloud Firestore에 가정, 구성원, 초대 코드, 접속 요청, 공동 장부 스냅샷을 저장한다.
- Firestore 보안 규칙으로 가족 공간과 구성원 권한을 검증한다.
- Firebase Hosting으로 정적 웹을 HTTPS 도메인에 배포한다.
- 브라우저 로컬 저장소 데이터는 사용자 계정 데이터로 이전할 수 있어야 한다.
- 원본 금융 파일은 기본적으로 서버에 저장하지 않는다.

## 8. 개인정보와 보안

- 금융기관 로그인 ID, 비밀번호, 인증번호를 수집하지 않는다.
- 업로드 파일은 브라우저에서 분석하고 원본을 장기 보관하지 않는다.
- 화면과 로그에 전체 카드번호나 계좌번호를 노출하지 않는다.
- 배포 시 모든 통신에 HTTPS를 적용한다.
- Google 비밀번호는 수집하거나 저장하지 않는다.
- Firebase 웹 설정은 공개 식별값으로 앱에 포함하고, Firebase 프로젝트 ID만 필요 시 환경 변수로 재정의한다. 클라이언트 보안 비밀번호는 사용하지 않는다.
- 한국투자 `App Key`와 `App Secret`은 Cloudflare Worker의 `KIS_APP_KEY`, `KIS_APP_SECRET` Secret으로만 관리하고 클라이언트 코드·Git 저장소에 포함하지 않는다.
- 사용자별 데이터 접근 권한은 Firestore 보안 규칙으로 검증한다.
- 가져오기, 수정, 삭제 같은 중요 작업은 추적 가능한 이력을 남긴다.

## 9. 반응형·접근성 요구사항

- PC는 사이드바, 모바일은 하단 내비게이션을 사용한다.
- 넓은 금융 표는 모바일에서 표 내부 가로 스크롤을 허용한다.
- 버튼과 입력란에는 의미 있는 레이블을 제공한다.
- 빈 상태에는 사용자가 다음에 해야 할 행동을 표시한다.
- 금액의 증가·감소는 색상만으로 구분하지 않고 부호와 문구를 함께 사용한다.
- 필터 변경 결과와 합계는 별도의 저장 동작 없이 즉시 반영한다.

## 10. 검증 기준

### 거래

- 우리장부 거래 양식의 날짜가 엑셀 표시일과 동일해야 한다.
- 카드·은행 파일에서 취소 또는 제외 대상 거래가 중복 지출로 등록되지 않아야 한다.
- 미지원 양식은 자동 실패 후 수동 열 연결로 진행할 수 있어야 한다.
- 같은 헤더 양식은 두 번째부터 저장된 열 연결을 사용할 수 있어야 한다.
- 필터 결과 건수, 거래표 행, 수입·지출·총액이 일치해야 한다.

### 혜택 카드

- 설정하지 않은 결제수단은 혜택 카드 영역에 표시되지 않아야 한다.
- 목표 사용액을 저장하면 달성률과 남은 금액이 즉시 계산되어야 한다.
- 수정·삭제 후 화면과 로컬 저장소가 일치해야 한다.

### 자산

- 다음 달에 기록이 없으면 이전 달 스냅샷을 그대로 불러와야 한다.
- 이어받은 달을 수정해도 이전 달 기록은 변하지 않아야 한다.
- 예금 월 예상이자는 `잔액 × 연이율 ÷ 12`와 일치해야 한다.
- 대출 월 예상이자는 `남은 원금 × 연 금리 ÷ 12`와 일치해야 한다.
- 예시 검증값: 남은 원금 12,000,000원, 연 6%인 경우 월 예상이자는 60,000원이다.
- 순자산은 원화 현금성 자산과 원화 투자 평가액에서 대출 원금을 뺀 값과 일치해야 한다.

### 빌드와 화면

- 프로덕션 빌드가 오류 없이 완료되어야 한다.
- PC와 모바일 주요 화면에서 텍스트와 버튼이 잘리지 않아야 한다.
- 거래가 없거나 자산이 없는 초기 상태에서도 오류 없이 안내를 표시해야 한다.

### 로그인과 공유

- 미로그인 사용자도 개인 장부 화면을 바로 표시하고, 설정 화면에서 Google 로그인을 선택할 수 있어야 한다.
- 인증되지 않은 사용자는 공동 장부 API를 읽거나 수정할 수 없어야 한다.
- 초대 코드는 생성 후 7일이 지나면 접속 요청에 사용할 수 없어야 한다.
- 초대 코드 또는 링크를 사용해도 소유자가 승인하기 전에는 대상 가정의 정보가 공개되지 않아야 한다.
- 소유자가 요청을 승인한 사용자만 동일한 가정의 구성원 목록에 표시되고 공동 장부를 사용할 수 있어야 한다.
- 한 사용자가 수정한 공동 장부가 새로고침 후 다른 구성원에게도 동일하게 표시되어야 한다.

## 13. 변경 이력 요약

1. 임의 샘플 거래·예산·자산을 제거하고 빈 상태에서 시작하도록 변경했다.
2. NH농협카드를 포함한 일반 카드 파일 인식 범위를 확장했다.
3. 지원하지 않는 파일은 실패시키지 않고 필요한 경우에만 수동 열 연결을 제공하도록 변경했다.
4. 엑셀 날짜가 하루 전날로 저장되는 시간대 문제를 수정했다.
5. 예산 수정, 저축 목표 수정, 고정비 관리 기능을 활성화했다.
6. 자산 기록을 이전 달에서 자동 이월하고 월별 수정본을 별도 보관하도록 변경했다.
7. 홈의 고정비 요약을 항목별 지출 원형 도표로 교체하고 지난달 대비 증감률을 추가했다.
8. 카드 미결제 요약을 지난달 총지출 비교로 교체했다.
9. 거래표 하단에 필터 기준 수입·지출·총액을 추가했다.
10. 사용자가 지정한 혜택 카드만 목표 사용액, 달성률, 혜택 설명과 함께 표시하도록 추가했다.
11. 대출·부채에 남은 원금과 연 금리 기반 월 예상이자 및 전체 합계를 추가했다.
